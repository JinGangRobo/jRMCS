# 控制器-云台

- 状态：待办
- 优先级：P0（dual-infantry 双 YAW 云台链）、P1（其余两轴机型）
- 影响机型：dual-infantry（P0）、mini-infantry、mec-hero（P1）；hero/deformable 为 v3 独有，仅记录
- 依赖主题：11（PID/滤波/数学，`filter::wrap_to_pi`、`filter::ExtendedKalmanFilter`、`pid::PidCalculator`）、04（`rmcs_msgs::{ChassisMode,GimbalMode}`）、05/06（IMU、电机、TF）、15（TF 与描述，`TwoAxisGimbalSolver` 依赖 `/tf`）、17（视觉子系统，`/auto_aim/*` 接口）
- 验收方式：交叉编译 arm64 通过；`clang-format` 通过；静态核对接口生产者/消费者；实车验证双 YAW 协同（top 回中、bottom 吃误差）、自旋提前量、pitch 限位

## 0. 本次核对的结论摘要

1. `dual_yaw_controller.cpp`：v2/v3 **逻辑等价**（仅 `filter::` 命名空间与 `RCLCPP_*` 细节）。
2. v3 另建 `smc_dual_yaw_controller.cpp`（`SmcDualYawController`），它其实是 **v2 `DualYawController` 的近似逐行拷贝**（同参数名、同接口名、同 SMC 公式），v3 的 `dual-infantry.yaml` 正是用它。→ 说明「双 YAW 控制器」实际已搬完，只是改了类名。
3. `dual_yaw_solver.cpp` 有**实质差异**：v3 参数化了 `spin_angle_bias` / `top_yaw_limit`，删除了 `/gimbal/bottom_yaw/angle` 输入与 `/gimbal/top_yaw/control_angle` 输出，并且 **top 目标转速不再减去 `estimated_bottom_yaw_velocity`**。v3 `dual-infantry.yaml` 把 `spin_angle_bias` 设为 **0.0**（v2 是硬编码 0.6）。
4. `simple_gimbal_controller.cpp` 在 v3 **缺失 v2 的电机离线门控（`depond_motors`）、`shift_control_clamp`、`joystick_left_bias_*`、云台自瞄扫描**；但 v3 `dual-infantry.yaml` 仍在写这些键 → **配置项静默失效**。
5. `two_axis_gimbal_solver.hpp` v3 属**重写**：新增 yaw 机械限位（`enable_yaw_limit`/`clamp_yaw_limit`）、删除 pitch 角输入、删除 4 个 debug 输出、删除 yaw/pitch 输出低通滤波与 ±π/3 的 yaw 误差限幅、删除 `SetControlDirection` 的 0.4 rad 平滑钳位、删除 `current_control_direction()`（v2 `simple_gimbal` 的自瞄扫描依赖它）。
6. `player_viewer.cpp`：v3 把 pitch 角输入换成 `/gimbal/player_viewer/raw_angle`（`int64_t`，**注册后未使用**）；新增 E/Ctrl 初始化角；修正 clamp 上下限顺序；scope 力矩 0.2 → 0.13。
7. v3 独有：`eccentric_dual_yaw.cpp`、`eccentric_dual_yaw_solver.hpp`、`hero_gimbal_controller.cpp`、`deformable_infantry_gimbal_controller.cpp`。

## 3. 差异清单

### D1 `dual_yaw_controller.cpp`（P2，等价）
- **diff -u 全文 39 行**，仅：
  - `utility::angle_wraper::wrap_to_pi` → `filter::wrap_to_pi`（2 处）
  - 新增 `#include <limits>`、`<rclcpp/logging.hpp>`
  - 末行换行
- **接口名/参数名完全一致**（`/gimbal/top_yaw/{target_angle_error,target_angle_velocity,control_torque}`、`/gimbal/bottom_yaw/*`、`/gimbal/yaw/velocity_imu`、`/gimbal/bottom_yaw/estimated_velocity`、`/debug/sliding_value`；`top_yaw_angle_*`/`top_yaw_velocity_*`/`bottom_yaw_smc_*`/`bottom_yaw_inertia`/`bottom_yaw_max_torque`/`bottom_yaw_accel_ff_alpha`/`top_yaw_angle_limit`）
- **风险**：无

### D2 v3 `smc_dual_yaw_controller.cpp`（P0）
- **v2 做法**：`DualYawController`
- **v3 做法**：`SmcDualYawController`（`smc_dual_yaw_controller.cpp`），与 v2 `DualYawController` **同公式、同参数、同接口**；差异仅：
  - `top_yaw_angle_limit_ = get_parameter_or("top_yaw_angle_limit", 0.9)`（v2 为 `get_parameter(...)` 必填）
  - 注释说明（「SMC-based dual yaw controller for dual-infantry」）
- **影响**：v3 dual-infantry（P0）实际使用的就是这份，等价于 v2
- **风险**：低。若将来同时需要「制动式」与「SMC 式」，需明确分工（v3 注释称旧版 `DualYawController` 保留给 hero）

### D3 `dual_yaw_solver.cpp`（P0，重点）
- **v2 做法**：
  - `constexpr double TOP_YAW_LIMIT = std::numbers::pi / 3.0`（L66）硬编码
  - 提前量：`+ (*control_mode_ == rmcs_msgs::ChassisMode::SPIN ? 0.6 : 0.0)`（L81）硬编码
  - `register_input("/gimbal/bottom_yaw/angle", bottom_yaw_angle_)`（L30）
  - `*top_yaw_target_velocity_ = *control_angle_velocity_ - *estimated_bottom_yaw_velocity_;`（L91）
  - 输出 `/gimbal/top_yaw/control_angle`（L117，`top_yaw_control_angle_`；写 `nan_`/`0.0`）
  - `BottomYawVelocityEstimator::update()` 返回 `estimated_state(1) / 4.0`
  - 估计器另有 `get_gimbal_absolute_velocity()`、`get_motor_relative_angle()`、`reset()` 等**未被调用**的接口
- **v3 做法**：
  - 参数化：`spin_angle_bias_ = get_parameter_or("spin_angle_bias", 0.6)`（L27）、`top_yaw_limit_ = get_parameter_or("top_yaw_limit", std::numbers::pi / 4.0)`（L30）
  - 提前量：`+ (rmcs_msgs::is_spining(*control_mode_) ? spin_angle_bias_ : 0.0)`（L88）
  - **删除** `bottom_yaw_angle_` 输入；**删除** `/gimbal/top_yaw/control_angle` 输出（无消费者，v2 亦无）
  - `*top_yaw_target_velocity_ = *control_angle_velocity_;`（L99，**不再减估计值**，v3 注释指出 v2 的估计量纲不对会使 top 乱冲）
  - 保留 `/4.0` 并写长注释说明「不能简单去掉」（实测 2026-10-14 去掉后上电即抖）
  - `normalize_angle/angle_difference` 改 `static`；删除未用接口
- **影响**：迁到 v3 后 **top yaw 目标转速语义变化**；`top_yaw_limit_` 与 `spin_angle_bias_` 变成可调
- **风险**：**高**。v3 `dual-infantry.yaml` 设 `spin_angle_bias: 0.0`（等于关闭自旋提前量）+ `top_yaw_limit: 0.7854`（比 v2 的 π/3≈1.047 更小），**与 v2 实车参数不等价**，需按实车重新整定或恢复为 0.6/π3

### D4 `simple_gimbal_controller.cpp`（P0）
- **v2 做法**：见 §1（`shift_control_clamp`、`joystick_left_bias_*`、`depond_motors` 离线门控 + `RCLCPP_WARN_THROTTLE` 提示、`value_abs_clamp()`、自瞄接管 + autopilot 扫描：`Eigen::AngleAxisd(scan_direction*0.0013, UnitZ)` 与 `sin((now & 0xFFF) * 0.001534 * 2)` 俯仰扫描）
- **v3 做法**：
  - 输入改为 `/auto_aim/should_control`、`/auto_aim/control_direction`（对接 `rmcs_auto_aim_v2`）
  - 新增 `two_axis_gimbal_solver.enable_yaw_limit(*this, yaw_upper_limit, yaw_lower_limit)`（L41-43）
  - 灵敏度：`joystick_sensitivity` 0.004 → 0.006；去掉 `value_abs_clamp` 与 `shift_control_clamp`
  - ~~depond_motors~~ / ~~joystick bias~~ / ~~scan~~ 全部不存在
- **影响**：
  1. v2 的「云台电机离线即停控并告警」在 v3 消失（离线检测只剩 `diagnosis`，且 diagnosis 在 v3 dual-infantry 未启用 → 见主题 12）
  2. v3 `dual-infantry.yaml` 里的 `shift_control_clamp` / `joystick_left_bias_y` / `joystick_left_bias_x` / `depond_motors` **无任何代码读取**（`grep -rn` 全仓库无命中）→ 静默失效
  3. 自瞄扫描（autopilot 巡航扫描）在 v3 无对应；v3 依赖视觉侧自行扫描
- **风险**：**高**（P0 机能相关性）

### D5 `two_axis_gimbal_solver.hpp`（P0/P1）
- **v2 做法**：见 §1；关键片段：
  - `SetControlDirection::update()` 含 `direction_control_clamp_angle_ = 0.4f` 的方向平滑（限制与当前控制方向夹角超过 0.4 rad 时按 `AngleAxisd{0.2, axis}` 步进）
  - `SetControlShift` 用 `last_yaw_error_` 抑制 yaw 抖动（`(last_yaw_error_ * yaw_shift_) > 0 && |last_yaw_error_| > 0.4` 时抑制 yaw_shift）
  - `calculate_control_errors()` 对 yaw 误差限幅 `±π/3`，并过 `yaw_output_filter_`/`pitch_output_filter_`（`LowPassFilter<>{5.0f, 1000.0f}`）
  - `current_control_direction()` 供 `SimpleGimbalController` 扫描使用
  - 4 个 `/debug/solver/{pitch_err,yaw_err,pitch,yaw}` 输出
  - `pitch.normalized();`（**未生效**，返回值被丢弃）
- **v3 做法**：重写
  - 新增 `enable_yaw_limit(component, yaw_upper_limit, yaw_lower_limit)`（注册 `/gimbal/yaw/angle`）与 `clamp_yaw_limit()`（把控制方向绕 Z 旋转到 `[yaw_cw_min_, yaw_cw_max_]` 区间内）
  - 删除 `/gimbal/pitch/angle` 输入、4 个 debug 输出、输出低通滤波、±π/3 yaw 误差限幅、`direction_control_clamp_angle_`、`last_yaw_error_` 抑制
  - `SetDisabled` 的判零改为 `|x|<1e-6 && |y|<1e-6`
  - `pitch.normalize();`（修正）
- **影响**：v3 换成「机械限位优先」，牺牲了 v2 的输出平滑与自瞄接管平滑；`current_control_direction()` 删除后 v2 式扫描无法直接迁移
- **风险**：中高。需实车确认自瞄接管瞬间是否有突变（v2 的 0.4 rad 平滑正是为此）

### D6 `player_viewer.cpp`（P1）
- **v2 做法**：`register_input("/gimbal/pitch/angle", gimbal_pitch_angle_)`（`double`）；E 键复位到 `upper_limit_`；`std::clamp(angle, upper_limit_, lower_limit_)`（顺序反了）；scope 力矩 ±0.2

## 4. 迁移方案（以 v3 为骨架）

**总原则**：双 YAW 链（`SmcDualYawController` + `DualYawSolver`）已在 v3，重点是**参数对齐**与**simple gimbal 的可用性补全**；不要回退 v3 的 `two_axis_gimbal_solver` yaw 限位能力。

1. **T09-1（P0）** `dual_yaw_solver` 参数对齐
   - 在 `dual-infantry.yaml` 的 `dual_yaw_solver` 块，按 v2 实车把 `spin_angle_bias` 从 `0.0` 恢复到 `0.6`（或实车重新整定），`top_yaw_limit` 与 v2 的 `π/3` 对齐（或实车整定）
   - 记录「v3 top 目标转速不再减 `estimated_bottom_yaw_velocity`」这一行为差异，作为实车 A/B 项
   - 保持 `/4.0` 不动（v3 注释有实测依据）
2. **T09-2（P0）** `SimpleGimbalController` 补回 v2 的可用性功能
   - `shift_control_clamp`（含 `value_abs_clamp()`）、`joystick_left_bias_x/y`
   - `depond_motors` 离线门控 + `RCLCPP_WARN_THROTTLE` 提示（与 v3 `AutoAim` 输入并存）
   - 若要恢复扫描，需先把 v2 的 `current_control_direction()` 加回 `TwoAxisGimbalSolver`，或改为在 v3 `SimpleGimbalController` 内部自行维护方向
   - 保留 v3 的 `/auto_aim/should_control`、`/auto_aim/control_direction` 命名（对接 `rmcs_auto_aim_v2`），**不要**退回 `/gimbal/auto_aim/*`
3. **T09-3（P0）** 决定 `two_axis_gimbal_solver` 的平滑策略
   - 候选 A：保留 v3 的 yaw 机械限位，另把 v2 的 `yaw_output_filter_/pitch_output_filter_`（5 Hz/1000 Hz）与 ±π/3 yaw 误差限幅重新加回（评估与 yaw 限位是否冲突）
   - 候选 B：保留 v3 现状，仅靠实车调 `yaw_upper_limit/lower_limit` 与 `SimpleGimbalController` 灵敏度
   - 建议先 A/B，把结论写回本文档
4. **T09-4（P1）** `player_viewer` 初始角参数化
   - 把 `kEInitViewerAngle`/`kCtrlInitViewerAngle` 换成 `get_parameter_or("e_init_angle", ...)`；删除未使用的 `/gimbal/player_viewer/raw_angle` 输入
5. **T09-5（P1）** 明确 `DualYawController`（v3 现存）与 `SmcDualYawController` 的分工，避免误配；在 config 注释中标注
6. **T09-6（P1）** 云台离线检测：与主题 12 协同，考虑给 dual-infantry 启用 `diagnosis`（`enable_motor_check: true`，motors 列表覆盖 `/gimbal/*`）
