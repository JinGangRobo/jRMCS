## 1. v2（reATRM）现状

### 1.1 共有形态

三机型结构与 dual_infantry 同构：`TopBoard`/`BottomBoard` 均 `private librmcs::client::CBoard(usb_pid)`，参数 `usb_pid_top_board`/`usb_pid_bottom_board`；设备驱动自带 ROS 注册；含 `device::Buzzer`、`device::Supercap(..., 28.5)`；`bottom` 板负责 `/referee/serial`（UART1）；TopBoard 用 `imu_bias_x/y/z` + `set_coordinate_mapping`。

### 1.2 dual_sentry

- 器件：top yaw `GM6020`、pitch `DM J4310`、左右摩擦轮 `M3508`、弹仓 `M3508`（`enable_multi_turn_angle`，`reduction_ratio 19*2`）、bottom yaw `GM6020`、4 轮 `M3508`；TopBoard 另有 `Gy614`（`/friction_wheels/temperature`，UART2）与 `Buzzer`。
- CAN/串口：TopBoard CAN1 `0x1FF`（[3]=feeder、[1]=top_yaw）、CAN1 `0x200`（[0]=right_friction、[1]=left_friction）；**CAN2 `0x4`** = pitch；接收 CAN1 `0x206(top_yaw)/0x202/0x201/0x208(feeder)`、CAN2 `0x214(pitch)`；UART `dbus` + UART2(GY614)。BottomBoard CAN1 `0x200`（4 轮）、`0x1FF`（[0]=bottom_yaw）；接收 `0x201..0x204`、`0x205`、`0x20c`(supercap)；UART1 裁判。
- 调试输出：`/debug/pitch/raw_angle`、`/debug/top_yaw/raw_angle`。

### 1.3 hero

- 器件：3 个摩擦轮 `M3508`（`/gimbal/{first,second,third}_friction`）、pitch `DM J4310`；bottom 4 轮 `M3508`、yaw `DM J4310`（`enable_multi_turn_angle`）、弹仓 `DM J4310`；含 `Buzzer`、`Supercap(28.5)`。
- CAN：TopBoard CAN1 `0x200`（3 摩擦轮 batch）、**CAN2 `0x9`** = pitch；接收 CAN1 `0x201..0x203`、CAN2 `0x219(pitch)`。BottomBoard CAN1 `0x200`（4 轮）、**CAN2 `0x4`**(feeder DM)、**CAN2 `0x2`**(yaw DM)；接收 `0x201..0x204`、CAN2 `0x214(yaw)`/`0x212(feeder)`/`0x20c`(supercap)；UART1 裁判。
- 调试输出：`/debug/pitch/raw_angle`、`/debug/pitch/temp`、`/debug/imu/{gx,gy,gz}_bais`。

### 1.4 mini_infantry

- 器件：top `GM6020` pitch（`/gimbal/pitch`）、2 摩擦轮 `M3508`；bottom 4 轮 `M3508`、`GM6020` yaw、`M2006` feeder；含 `Buzzer`、`Supercap(28.5)`。
- CAN：TopBoard CAN1 `0x200`（摩擦轮）、CAN1 `0x1FF`（pitch）；接收 CAN1 `0x201/0x202/0x205(pitch)`。BottomBoard CAN1 `0x200`（4 轮）、CAN1 `0x1FF`（[1]=yaw、[2]=feeder）；接收 `0x201..0x204`、`0x207`、`0x206`、`0x20c`(supercap)；UART1 裁判。
- 调试输出：无（v2 mini 未注册 debug raw_angle）。

### 1.5 pid_tune_tool

- 文件：`.../hardware/model/pid_tune_tool.cpp`；类 `rmcs_core::hardware::PidTuneTool`（`DualInfantry` 同构的双板结构）。
- 插件：`plugins.xml` 第 5 行 `rmcs_core::hardware::PidTuneTool`。
- config：`bringup/config/pid-tune-tool.yaml`。关键参数：`usb_pid_top_board: 0xa513`、`usb_pid_bottom_board: 0x4ca4`、`motor_zero_point: 0`、`velocity_step: 1.0`、`step_time: 400.0`、`imu_bias_x/y/z: 0`。
- 接口：`/tf`；`/top/imu/gz`、`/top/imu/gy`、`/bottom/imu/gz`、`/bottom/imu/gy`（第 99–100、180–181 行）；`/motor/raw_angle`、`/motor/control_velocity` 等 `/motor/*`（第 183–184 行）。配套 `velocity_pid_controller`（`measurement: /top/imu/gz`）。

### 1.6 legacy 目录

- v2：`hardware/model/legacy/{infantry.cpp_, steering-hero.cpp_, steering-infantry.cpp_, tunnel_infantry.cpp_}`（4 个，均为 `.cpp_` 禁用形态）。

| dual_sentry | pitch | `0x214`(CAN2) | `kJ4310`(固定 id) | ✅ |

## 4. 迁移方案（以 v3 为骨架）

1. **三机型（dual_sentry/hero/mini_infantry）**：维持 v3 现状，只做「校正与补齐」：
   - 填真实 `board_serial_top_board/bottom_board`（替换 `placeholder-*`）。
   - 确认 yaw 电机控制模式（`kGM6020Voltage` vs `kGM6020`）并重标转矩（同主题 06 M5）。
   - 校核 `Bmi088Ekf::Config{body_to_sensor}`：hero 已有矩阵与注释；`dual_sentry`/`mini_infantry` 目前为默认单位阵，需比对 v2 的 `set_coordinate_mapping`（`dual_sentry.cpp:141`、`mini_infantry.cpp:116`）逐一确认（**未核实**）。
   - 决定蜂鸣器：统一按主题 05 的结论处理（三机型与 dual_infantry 同）。
   - 修正任何仍引用 `/…/velocity_filtered` 的配置。
2. **pid_tune_tool（工具机型）**：二选一——
   - **A. 移植**：以 v3 新 API 重写 `hardware/pid_tune_tool.cpp`（双板、`kDbus`、`DjiMotor`/`DmMotor`、`Bmi088Ekf`），注册 `plugins.xml`，补 `config/pid-tune-tool.yaml`（可沿用 v2 参数键，但 `usb_pid_*`→`board_serial_*`）。
   - **B. 替代**：正式弃用 `PidTuneTool`，改用 `controller::identification::StaticTorqueTestController` / `SweptFrequencyController` + `debug::ValueCollector`，并补一份可运行的 config（当前这些组件无任何启用示例）。
   - 建议：若本阶段不需要参数辨识，先在文档/issue 中明确"暂缓"，避免"隐形丢失"。
3. **legacy**：不阻塞；如需恢复 v2 独有的 4 个 legacy 机型，单独立项（且需先过 v3 新 API 迁移）。
4. **config 一致性**：`diagnosis` 参数表以 v3 `Diagnosis` 实现为准；`enable_aim_check`/`enable_nav_check` 的去留需与 `diagnosis` 组件核对。
