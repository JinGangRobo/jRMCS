- 状态：待办

## 0. 本次核对的结论摘要（先看这里）

1. **v2 的「底盘扭矩分配/自旋平移优化」已完整搬运到 v3**（`JOmniWheelController` = v2 `omni_wheel_controller.cpp` 最终版，含 `calculate_wheel_control_torques()` 的 *Torque redistribution* 与 `spinning_bais_coefficient_` 自旋偏置补偿）。逐行 `diff -u` 后仅剩无害差异（类名、`filter::` 命名空间、缺失的 `power_limit` 生产者回退、const 修饰）。**没有漏搬。**
2. **`JChassisPowerController` 与 v2 `chassis_power_controller.cpp` 逻辑完全等价**（逐行 diff 只有头文件与类名差异）。
3. v3 仓库同时存在**两套**底盘功率控制器（上游新版 `chassis_power_controller.cpp` 与迁移版 `j_chassis_power_controller.cpp`）与**两套**全向轮控制器思路（`j_omni_wheel_controller.cpp` 有扭矩重分配；`deformable_omni_wheel_controller.cpp` 没有）。活跃 config 只使用 J 前缀版本。
4. **`ChassisController` 已明显分叉**（v3 换成导航/爬坡/打滑看门狗/多对齐模式；v2 是遥控/操作辅助/autopilot/单 SPIN 模式）。v2 的 `OperateLogic`（操作辅助）在 v3 **完全没有对应实现**。
5. v3 `dual-infantry.yaml` **没有 `chassis_power_controller`、没有超电**，靠 `JOmniWheelController` 的 `power_limit_default: 45.0` 兜底；`/chassis/boost` 在 v3 无人生产。

- **风险**：中。建议迁移时按实车重新整定，并保留 `spinning_bias_adjust` 旋钮在线的整定方式

**总体原则**：v3 的 `JOmniWheelController` / `JChassisPowerController` **保持不变**（已等价）。需要处理的是 **D4/D5/D9** 三个结构性缺口，以及 D3/D8 的收尾。

优先级顺序（依赖 11 → 08）：

1. **T08-1（P0，必做）** `OperateLogic` 移植

   - 在 `rmcs_core/src/controller/chassis/` 新增 `operate_logic.cpp`（类名建议 `OperateLogic`，不改 v2 接口名）
