
`rmcs_core/CMakeLists.txt`（v2）：

```cmake
file (GLOB_RECURSE PROJECT_SOURCE CONFIGURE_DEPENDS
```

### 2.3 交叉编译（v3 新增能力）

- `.devcontainer/devcontainer.json`：`dockerComposeFile: [docker-compose.yml, .generated/docker-compose.local.override.yml]`；`initializeCommand` = `generate-local-override.sh` + `probe-host-tools.sh`；`postCreateCommand` = `setup-shell-history.sh` + `bootstrap-tools.sh`；`workspaceFolder: /workspaces/RMCS`；**7 个扩展**（clangd、pylance、python、debugpy、cmake-intellisence、cspell、git-graph）。
- `.devcontainer/scripts/`：
  - `generate-local-override.sh`：按宿主环境生成 `.generated/docker-compose.local.override.yml`（代理变量、`DISPLAY`、把宿主 `~/.codex`、`~/.claude`、`~/.config/opencode`、`~/.local/share/opencode`、`~/.agents/skills`(只读) 等挂进容器）。
  - `probe-host-tools.sh`：探测宿主 `codex/claude/opencode/lark-cli` 版本 → `.generated/host-tools.manifest`（实测 `opencode=2.0.32`，其余 absent）。
  - `bootstrap-tools.sh`：按 manifest 用 npm 在容器内装同版本 CLI（opencode 按 major≥2 选 `@opencode/cli`，否则 `opencode-ai`）。
  - `setup-shell-history.sh`：`~/.zsh_history` → 仓库 `.devcontainer/.zsh_history` 软链接。
- `.vscode/settings.default.json`：`clangd.arguments = ["--header-insertion=never"]` + 一份 `cSpell.words`；**注意**其 `python.autoComplete/analysis.extraPaths` 仍写死 `/opt/ros/humble/...`（疑似残留，见 §7）。

### 2.6 CI（`.github/workflows/update-image.yml`，1 个 workflow，12 600 B）

- 触发：`workflow_dispatch` + `push` 到 **`main-jrmcs`**，且 `paths` 限 `Dockerfile`、`.github/workflows/update-image.yml`、`.script/template/`、`.script/build-rmcs-cross`、`rmcs_ws/toolchain.cmake`（commit `38c174b chore(action): change workflow trigger branch to main-jrmcs`）。
- 镜像：`mide233/jrmcs-base`、`mide233/jrmcs-develop`、`mide233/jrmcs-runtime`（commit `d2f030c chore(docker): rename rmcs images to jrmcs and push to mide233 registry`）。
- 4 个 job：
  1. `build_base`：矩阵 `amd64`(ubuntu-latest) / `arm64`(ubuntu-24.04-arm)，`target: jrmcs-base`，`push-by-digest` + `cache-from/to: type=gha`。
  2. `build_images`：`needs: build_base`；装 SSH key（secrets `CONTAINER_ID_RSA[_PUB]`）；用 digest 作为 `SYSROOT_IMAGE_AMD64/ARM64` 构建 `jrmcs-develop`、`jrmcs-develop-full`、`jrmcs-runtime` 三个 target 并出 digest。
  3. `verify_images`：`needs: build_images`；对**对向架构**做 smoke：`docker run` 内断言 `/opt/sysroots/<cross>` 存在、交叉编译器存在、`./.script/build-rmcs-cross --target-arch <cross> --packages-up-to rmcs_executor` 成功、`readelf -h` 匹配 `AArch64`/`X86-64`。
  4. `promote`：用 `docker buildx imagetools create` 把各架构 digest 合成 `latest` / `latest-full` manifest list，并 `imagetools inspect`。
- **注意**：CI smoke 只到 `rmcs_executor`（`--packages-up-to`），而 `AGENTS.md` §3 的验收要求是**全量**（含 `rmcs_core`）；`docs/zh-cn/cross_build.md` §5 也明确「CI 只保留 `rmcs_executor` 最小 smoke，避免高频业务改动阻塞镜像推送」。

### 2.7 部署 / 同步

流程（`README.md` + 脚本）：`set-remote <host>`（mDNS/扫描 → 写 `~/.ssh/config Host remote`，含 `# RMCS_TARGET_ARCH=`）→ `ssh-remote`（`ssh -X remote`，端口 2022）→ `sync-remote`（unison 监听，`install[-cross-<arch>]` → `remote://rmcs_install`，`--with-build` 时 build → `remote://rmcs_build`）→ 容器内 `set-robot <name>` + `service rmcs restart|attach`。快捷：`build-rmcs && wait-sync && attach-remote -r`。`wait-sync` 通过 `/tmp/sync-remote` UNIX socket 与 `sync-remote` 通信。

- 架构自适应（commit `3534a6c`）：`sync-remote` 读远端 `# RMCS_TARGET_ARCH=`，与 `platform.machine()` 比较，自动选 `install` 或 `install-cross-<arch>`；`set-remote` 增加 `--arch`。
- `sync-remote` 用 `unison -force <src> -follow 'Name *'`，因此 `--symlink-install` 的软链接被解引用为上载实体文件。
- **文档与实现不一致**（重要）：`docs/zh-cn/cross_build.md` §4 写「默认启用 `--merge-install` / **不使用 `--symlink-install`**」，但脚本实际带 `--symlink-install`（commit `1f0d1a7 fix(build): enable symlink installation in cross build script` 之后）。文档未同步。

## 4. 迁移方案（以 v3 为骨架）

**总原则**：v3 工程链路已全面**超过** v2（多阶段镜像、交叉编译、CI、远程同步）。因此本主题**不做反向移植**，只做三件事：**（A）补齐 v3 覆盖不到的能力**、**（B）修掉 v3 自身的缺陷**、**（C）为其他主题的移植提供构建/验证支撑**。

### A. 补齐 v3 缺失（来自 v2，价值有限但成本低）

1. `format-all`：若团队确实需要批量格式化，可在 `.script/` 增加 `format-rmcs`（沿用 v2 `find ... -exec clang-format -i --style=file`，但根改为 `rmcs_ws/src`，并排除归档 `*_` 与子模块）。**可选**。
2. `.clang-format` 对 `AlignArrayOfStructures` 的偏好：若团队要保留 v2 风格，需**全仓统一**后再改，禁止只改文件造成噪声。**默认不动**。

### B. 修复 v3 自身缺陷

1. **文档纠偏**：修正 `docs/zh-cn/cross_build.md` §4，把「不使用 `--symlink-install`」改为「默认启用 `--symlink-install` 与 `--merge-install`」，与 `.script/build-rmcs-cross` 一致（commit `1f0d1a7`）。
2. **CI 覆盖率**：在 `verify_images` job 中把 smoke 从 `--packages-up-to rmcs_executor` 提升到至少 `--packages-up-to rmcs_core`（`docs/zh-cn/cross_build.md` §5 的「本地快速自检」已覆盖 `rmcs_core`，CI 可对齐；若担心耗时，可作为独立 job 或 `workflow_dispatch` 手动触发）。
3. **`.vscode/settings.default.json` 的 ROS 版本残留**：`/opt/ros/humble/...` 与镜像的 jazzy 不符（**未核实**是否有意为之）。
4. **`hikcamera` / `serial` 依赖声明**与源码树不一致（同主题 01 §3 #4/#5）：在容器内验证交叉编译是否真的能找到这两个包，否则在 `README`/`AGENTS.md` 明确「先装 `ros-jazzy-serial-driver`、自瞄需外部 `hikcamera`」。

### C. 为移植提供支撑

1. 所有移植代码的验证统一走：
   `./.script/build-rmcs-cross --target-arch=arm64 --packages-skip rmcs_auto_aim_v2 --executor sequential`
2. 使用 `switch-compile-commands arm64` 为 clangd 提供交叉编译数据库，单文件快检按 `AGENTS.md` §9（复用 `rmcs_ws/build-cross-arm64/rmcs_core/compile_commands.json` 的命令，`-c` → `-fsyntax-only`）。
3. 迁入 `rmcs_core` 的 v2 代码按 **C++23** 审查；涉及 `fast_tf`/`rmcs_msgs`/`rmcs_description` 公开头时注意这些包仍为 **C++20**。
4. **禁止**把 v2 的 `librmcs` 子模块或 `libusb` 直链方式带入 v3：一律使用 v3 的 `librmcs-sdk`（FetchContent）。
