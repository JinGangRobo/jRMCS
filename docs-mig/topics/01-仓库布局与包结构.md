## 4. 迁移方案（以 v3 为骨架）

**总原则**：v3 的布局契约（`rmcs_ws/src/<pkg>`、`rmcs_core/src/{hardware,filter,...}`、`plugins.xml` 注册、`rmcs_bringup/config/<robot>.yaml`）**不改**；把 v2 资产「翻译」到该契约下。

1. **硬件模型落点**：一律放入 `rmcs_core/src/hardware/<robot>.cpp`（扁平，不建 `model/`）；配套设备驱动放 `rmcs_core/src/hardware/device/*.hpp`。
2. **数学工具落点**：放 `rmcs_core/src/filter/*.hpp`（v2 的 `src/utility/` → v3 `src/filter/`）。
3. **归档约定**：不使用/被取代的源码移到同级 `legacy/` 并追加 `_`（`.cpp_`/`.yaml_`），**同时**删除 `rmcs_core/plugins.xml` 中对应 `<class>`（避免 v2 式残留）。
4. **config 落点**：`rmcs_bringup/config/<robot>.yaml`，与 v2 `bringup/config/*.yaml` 一一对应（含 `rmcs_executor.ros__parameters.components` + 顶层组件参数块）。
5. **丢失包的处置**（需决策，见第 7 节）：
   - `hikcamera` / `serial`：在 v3 保持 `<depend>`，但需确认由镜像或 rosdep 提供；否则在对应包的 `package.xml` 中显式标注或恢复为 submodule（**倾向**：确认镜像已提供，不改 `.gitmodules`）。
   - `atrm_interfaces`：若 P0（dual-infantry）功能不依赖 `CmdGimbal`/`SupercapInfo`，则不迁；否则在 `rmcs_msgs` 中新增等价 msg。
6. **librmcs 迁移**：以 v3 的 `FetchContent` + `librmcs-sdk` 为准，v2 的 `rmcs_core/librmcs/librmcs/*` 头文件**不复制进仓库**；仅在必要时按 v3 SDK 头文件路径改写 include（详见主题 05）。
7. **`rmcs_auto_aim_v2`**：保持 v3 submodule revision（`8df0266e`），**不**回退到 v2 的 `2c3122f8`；v2 自瞄的差异在主题 17 单独处理。

## 8. 阶段三收尾结论（2026-10-19）

本节对上方 §7 的未决项给出定案，并更正早期描述中不准确之处。

1. **§7-1 / §7-2 结案（`serial` / `hikcamera` / sysroot）**：
   - `serial` / `hikcamera` **不是** v3 交叉编译的阻碍。实测：`rmcs_auto_aim_v2` 依赖的相机 SDK 是海康 `MVSUSB3Core`，而 arm64 sysroot **已提供**它（`/opt/sysroots/arm64/opt/mvs-usb3-core`，`CMakeCache.txt` 中 `MVSUSB3Core_DIR:PATH=…/lib/cmake/MVSUSB3Core`）。
   - `rmcs_auto_aim_v2/package.xml` 的 `<depend>hikcamera</depend>` 是**陈旧遗留**：`CMakeLists.txt` 中没有任何 `find_package(hikcamera)`，`capturer.cpp` 的 `#include "hikcamera.hpp"` 指向包内本地头文件 `src/io/capturer/hikcamera.hpp`。
   - 取证：不带 `--packages-skip rmcs_auto_aim_v2` 的 arm64 交叉编译中，`build-cross-arm64/rmcs_auto_aim_v2/…/io/capturer/capturer.cpp.o` 与 `librmcs_auto_aim_v2_component.so` 经 `readelf -h` 均为 `Machine: AArch64`。⇒ 此前惯用的 `--packages-skip rmcs_auto_aim_v2` **并非必需**。
2. **§7-3 结案（`atrm_interfaces`）**：**不迁移**。全仓 `grep -rn atrm_interfaces` 仅命中其自身的 `package.xml:4` 与 `CMakeLists.txt:2`，**零外部消费者**；物理路径 `/workspaces/reATRM/src/interface/interface/`（目录名与包名不一致），仅含 `package.xml`、`CMakeLists.txt`、`msg/CmdGimbal.msg`、`msg/SupercapInfo.msg`。jRMCS(v3) 无对应包，迁移机型亦未使用。
3. **§7-4 结案（`pid-tune-tool`）**：v3 已用「方案 B」落地——新增 `rmcs_bringup/config/pid-tune-tool.yaml`，以 `hardware::DualInfantry` + `controller::identification::{SweptFrequencyController,StaticTorqueTestController}` + `debug::ValueCollector` + `broadcaster::ValueBroadcaster` 取代 v2 的 `PidTuneTool` 硬件模型。
4. **描述更正**：早期背景描述中「urdf/TF 差异」的说法**不成立**——实测 `rmcs_description/tf_description.hpp` 两版 md5 完全一致，v2 的 `RawImu` link/joint 早已存在；真实差异只有 v3 新增 `sentry_description.hpp` 与 fast_tf 去掉 `fast_tf_dummy`（详见主题 15）。
5. **跨仓 `.clang-format` 差异（登记，未改配置）**：reATRM(v2) 与 jRMCS(v3) 的根 `.clang-format` 仅两处不同——(a) v2 独有 `AlignArrayOfStructures: Right`；(b) 嵌套键缩进宽度 v2 为 4 空格、v3 为 2 空格（不影响解析结果）。**阶段三决策：保持 v3 现状不动**，仅在从 v2 移植源码时注意避免格式噪声 diff。
